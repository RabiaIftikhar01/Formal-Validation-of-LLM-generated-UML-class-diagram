' This class diagram models the core components of a university's digital learning environment.
' It adheres to good design practices for extensibility, maintainability, and clarity.

' Design Practices Applied:
' 1. Simplicity: Focuses on essential domain entities and relationships, avoiding unnecessary complexity.
' 2. Naming Convention: Class names are singular nouns (e.g., User, Course, Enrollment).
' 3. Short Names: Class and attribute names are concise.
' 4. Consistent Case: PascalCase for classes, camelCase for attributes/methods.
' 5. Attribute Assignment: Attributes are carefully placed in their most relevant classes.
' 6. Operations per Class: Each class has a clear set of responsibilities and relevant operations.
' 7. Classes with Operations: All classes (except enums) encapsulate both data and behavior.
' 8. Manageable Responsibilities: Classes are not overloaded with too many operations.
' 9. Access Methods: Public methods are provided for accessing and manipulating class data.
' 10. Operation Categorization: Public methods serve as implementors or accessors.
' 11. Reduced Relationships: Relationships are kept to a necessary minimum.
' 12. Unidirectional Associations: Used where appropriate (e.g., NotificationService to User) for loose coupling.
' 13. No Multi-level Inheritance: Only single-level inheritance is employed.
' 15. Multiplicity: Clearly defined for all associations, reflecting business rules.
' 16. Relationship/Role Names: Used to clarify the purpose of associations.
' 20. Association Class: `Enrollment` is modeled as an association class to hold attributes specific to the relationship between Student and Course.
' 23. Descriptive Names: Clear and meaningful names are used for all elements.
' 24. Consistent Style: Uniform notation and layout for improved readability.
' 27. Loose Coupling: Components like `NotificationService` are designed to be independent and reusable.

' Abstract base class for all users in the system (Student, Instructor)
abstract class User {
    - userId : String
    - name : String
    - email : String
    + {abstract} getInfo() : String ' Provides general information about the user
    + receiveNotification(message : String) : void ' Allows a user to receive a notification
}

' Represents a student user, capable of browsing, enrolling, and tracking courses
class Student extends User {
    + browseCourses() : List<Course> ' Enables students to view available courses
    + enrollInCourse(course : Course) : Enrollment ' Allows a student to enroll in a specified course
    + viewAnnouncements() : List<String> ' Provides access to course announcements
    + trackEnrollmentStatus(enrollment : Enrollment) : EnrollmentStatus ' Checks the status of a specific enrollment
}

' Represents an instructor user, authorized to create, update, and notify about courses
class Instructor extends User {
    + createCourseOffering(title : String, description : String, level : String) : Course ' Creates a new course offering (Undergraduate or Postgraduate)
    + updateCourseMaterial(course : Course, material : String) : void ' Updates learning materials for a given course
    + sendNotificationToStudents(course : Course, message : String) : void ' Initiates sending a notification to students of a specific course
}

' Abstract base class for all courses offered by the university
abstract class Course {
    - courseId : String
    - title : String
    - description : String
    + getCourseId() : String ' Accessor for the course identifier
    + getTitle() : String ' Accessor for the course title
    + getDescription() : String ' Accessor for the course description
    + {abstract} getLevel() : String ' Defines the academic level of the course (e.g., Undergraduate, Postgraduate)
    + notifyEnrolledStudents(message : String) : void ' Delegates notification sending to the NotificationService for enrolled students
}

' Concrete class for undergraduate level courses
class UndergraduateCourse extends Course {
    + getLevel() : String
}

' Concrete class for postgraduate level courses
class PostgraduateCourse extends Course {
    + getLevel() : String
}

' Enum to represent the possible states of a student's enrollment
enum EnrollmentStatus {
    Waitlisted
    Active
    Completed
}

' Association class representing the specific instance of a student's enrollment in a course.
' It holds attributes related to the relationship itself.
class Enrollment {
    - enrollmentDate : Date
    - status : EnrollmentStatus
    + getEnrollmentDate() : Date ' Accessor for the enrollment date
    + getStatus() : EnrollmentStatus ' Accessor for the current enrollment status
    + updateStatus(newStatus : EnrollmentStatus) : void ' Changes the enrollment status
}

' A dedicated service responsible for sending notifications to users
class NotificationService {
    + sendNotification(message : String, recipient : User) : void ' Sends a notification to a single user
    + sendBatchNotification(message : String, recipients : List<User>) : void ' Sends a notification to multiple users
}

' Association Class: Enrollment represents the link between Student and Course
' A Student can have 0 to many Enrollments.
Student "1" -- "0..*" enrolledIn
' A Course can have 0 to many Enrollments.
Course "1" -- "0..*" hasEnrollment
' Explicitly marks Enrollment as an association class between Student and Course.
(Student, Course) .. Enrollment

' An Instructor manages (creates and updates) multiple Courses. Each Course is managed by one Instructor.
Instructor "1" -- "0..*" Course : manages >

' A Course can trigger notifications (e.g., for announcements, deadlines).
' It delegates this responsibility to the NotificationService.
Course --> NotificationService : triggers >

' The NotificationService delivers notifications to Users.
NotificationService --> User : deliversTo >

' An Instructor utilizes the NotificationService to send notifications to students.
Instructor --> NotificationService : uses >
