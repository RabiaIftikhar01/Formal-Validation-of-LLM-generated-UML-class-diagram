**Design Rationale:**

1. **Decorator Pattern for User Roles**: Applied the decorator pattern to allow users to have multiple roles dynamically (e.g., a user can be both student and instructor), ensuring extensibility without modifying core User class.

2. **Singleton Pattern**: Used for `NotificationService` and `AuthorizationService` to ensure single shared instances that coordinate notifications
