' Charge Hierarchy (Component pricing rules)
abstract class Charge {
    - description: String
    - unitPrice: double
    - quantity: int
    -- Operations --
    + {abstract} calculateAmount(): double
    + getDescription(): String
    + getUnitPrice(): double
    + getQuantity(): int
}

class ProcedureCharge extends Charge {
    - procedureCode: String
    -- Operations --
    + calculateAmount(): double
}

class MedicationCharge extends Charge {
    - medicationCode: String
    -- Operations --
    + calculateAmount(): double
}

class DiagnosticTestCharge extends Charge {
    - testCode: String
    -- Operations --
    + calculateAmount(): double
}

class RoomCharge extends Charge {
    - roomType: String

    -- Operations --
    + calculateAmount(): double
}

' Notes for clarity
note left of BillProcessingService : Orchestrates bill generation,\ndetermines and applies billing policies.
note right of BillingPolicy : Strategy pattern for flexible\nruntime policy changes based on patient type.
note top of Charge : Abstract base for all billable items,\neach with independent pricing rules.
note left of Patient : Patient type (e.g., INSURED, SELF_PAY)\ndetermines the applicable billing policy.
