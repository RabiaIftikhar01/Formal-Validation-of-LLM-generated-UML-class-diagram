' General Design Notes:
' 1. Strategy Pattern is used for Billing Policies (IBillingPolicy and its concrete implementations)
'    to allow interchangeable billing logic at runtime without modifying the BillGenerator.
' 2. Polymorphism is used for different Charge types (Charge and its subclasses) to handle
'    independent pricing rules for procedures, medications, diagnostics, and room occupancy.
' 3. Strong separation is maintained between Patient data, Billing Policies, and Charge components
'    to enhance extensibility and maintainability.
' 4. The BillItem class acts as an association class, facilitating flexible linking of charges
'    with specific quantities and prices at the time of billing, preventing clutter in Bill or Charge.
' 5. Naming conventions: Classes in PascalCase, attributes and methods in camelCase.
' 6. The design aims for loose coupling and high cohesion to ensure the system is easy to
'    integrate, test, and maintain, and extensible for future regulatory changes.

' Define the Patient and related information

        - String reimbursementLimits
        - String coPaymentStructure
        --
        + getPolicyNumber() : String

        + getCoverageRules() : String

        + getCoPaymentStructure() : String
    }

    Patient "1" -- "0..1" InsuranceDetails : has >
    Patient "1" -- "1" PatientType : has a
}

        --
        + addBillItem(item : BillItem) : void

        + getBillId() : String
        + getBillingDate() : Date
        + getTotalAmount() : BigDecimal
        + getBillItems() : List<BillItem>
    }

    class BillItem {
        - int quantity
        - BigDecimal unitPriceAtBilling
        - BigDecimal itemTotal
        --
        + calculateItemTotal() : BigDecimal
        + getQuantity() : int
        + getUnitPriceAtBilling() : BigDecimal
        + getCharge() : Charge
    }

    class BillGenerator {
        - IBillingPolicy currentPolicy
        --
        + generateBill(patient : Patient, charges : List<Charge>) : Bill
        - determineBillingPolicy(patient : Patient) : IBillingPolicy
        + setBillingPolicy(policy : IBillingPolicy) : void
    }

    Bill "1" *-- "0..*" BillItem : contains >
    BillGenerator "1" o-- "1" IBillingPolicy : uses >
    BillGenerator ..> Patient : generates bill for >
    BillGenerator ..> Bill : creates >
}

        + {abstract} calculatePrice() : BigDecimal

    class ProcedureCharge {
        - String procedureCode
        - String procedureName

    class MedicationCharge {

        --

    }

    class DiagnosticTestCharge {
        - String testCode
        - String testName

        - String roomType
        - BigDecimal dailyRate

    Charge <|-- ProcedureCharge
    Charge <|-- MedicationCharge
    Charge <|-- DiagnosticTestCharge
    Charge <|-- RoomCharge

    BillItem "0..*" -- "1" Charge : references >
}

note "The Strategy Pattern allows billing logic to be swapped at runtime\nwithout modifying the BillGenerator, enabling easy adaptation to\nchanging regulations and contractual updates." as N1
IBillingPolicy .. N1

note "Polymorphism enables different charge types to have their own pricing rules,\nensuring extensibility for new types of services and charges." as N2
Charge .. N2

note "BillGenerator determines the appropriate billing policy (Strategy) based on\nthe patient's PatientType and insurance details, fulfilling US-SYS1." as N3
BillGenerator .. N3

note "BillItem captures the specific state of a charge at the time of billing\n(quantity, unit price after any initial discounts/rules applied), ensuring\nbill consistency and preventing data redundancy within the Bill." as N4
